# 发布检查清单

## 当前可用能力

- 账号密码登录：妈妈、爸爸、小柚子。
- Cookie 登录保持，退出登录会清除会话。
- 支持在 `我的 / 设置 / 修改密码` 修改当前身份密码；成功修改密码前会自动生成一次手动备份。
- 忘记密码时可用 `npm run user:reset-password -- 身份 新密码` 重置；重置前会自动生成一次手动备份和一份账号文件单独备份。
- 妈妈可管理所有任务。
- 爸爸可新增任务，并编辑/删除自己创建的任务。
- 小柚子只看自己的任务。
- 家庭待办、个人待办、小柚子学习任务分区展示。
- 首页显示逾期、今天、明天、后天、本周任务。
- 清单页按时间顺序展示，可搜索和筛选。
- 清单页支持按分类、负责人、未完成/已完成筛选。
- 小柚子页保留已完成任务划线展示。
- 任务支持标题、备注、负责人、任务日期、最晚完成日期、优先级、提醒、评论。
- 任务完成后记录完成人和完成时间。
- 小柚子任务支持小红花奖励和爸爸/妈妈确认。
- 小柚子任务进入待确认后可恢复未完成，避免误点。
- 小精灵支持小红花余额、等级、开心值和喂养。
- 每周重复任务完成后自动生成下一次；小柚子任务确认后生成下一次。
- 回收站支持恢复和清空；妈妈处理全部，其他身份只处理自己可管理的任务。
- 清空回收站前会自动生成一次手动备份。
- 冒烟测试会验证手动备份整包恢复，恢复前会自动生成 `before-manual-restore` 备份。
- 手动备份 README 会标明关键文件状态，方便确认任务、账号和小精灵数据是否都在。
- 提醒设置按身份保存。
- 普通任务提醒默认只提醒负责人；小柚子待确认任务提醒给爸爸和妈妈。
- 页面保持打开时，会在回到前台、恢复网络和定时间隔时轻刷新，降低跨天后提醒和逾期状态滞后的概率。
- 妈妈设置页可查看数据安全状态、手动备份数量、最近备份；如果没有备份、备份超过 7 天、最近备份缺少关键数据文件，或手动备份积累太多，会提示处理。
- 本地 JSON 持久化，支持自动快照、手动备份、自检、修复、恢复。
- 基础 PWA 安装体验，包含 SVG、192 PNG 和 512 PNG 图标。
- `npm run app:status` 可快速确认预览服务是否打开，并给出电脑和手机同 Wi-Fi 访问地址。

## 每次交给家人试用前

可先按 `docs/TRIAL_GUIDE.md` 走一遍家庭试用流程。

最省心的方式是先跑一键检查：

```bash
npm run app:trial-check
```

它会检查真实数据、资源和 TypeScript，再用临时数据跑完整冒烟测试，最后确认临时测试没有污染类型配置。

1. 确认数据自检通过。

```bash
npm run data:check
```

如果这里提示有人还在使用默认密码 `123456`，正式试用前先让对应身份进入 `我的 / 设置 / 修改密码`。如果提示手动备份太久没做，先运行 `npm run data:backup`。

2. 确认应用快速健康检查通过。

```bash
npm run app:doctor
```

这一步会同时检查数据文件、必要资源和 TypeScript 类型。

3. 启动预览。默认固定用 3035，避免临时换端口后打开错链接。

```bash
npm run app:preview
```

4. 手机或浏览器打开。

```text
http://localhost:3035/
```

手机真机试用时，不要用 `localhost`；让手机和电脑连同一个 Wi-Fi，打开 `npm run app:preview` 输出的 `手机同 Wi-Fi` 地址。
如果链接打不开，先运行 `npm run app:status`，确认服务是否正在运行以及应该打开哪个地址；如果状态命令被当前环境限制，但浏览器能打开打印出的地址，说明应用服务通常是正常的。

## 正式部署前

1. 手动备份数据。

如果只是运行下面的 `app:release-check`，可以不用停本地预览；它会使用临时数据目录和独立的 `.next-doctor-build` 构建缓存。运行正式构建 `npm run app:build` 或直接 `npm run build` 前，再停掉 `npm run app:preview`。

```bash
npm run data:backup
```

2. 运行正式发布前检查。

```bash
npm run app:release-check
```

这一步会跑试用完整检查和隔离构建检查，不会生成正式启动用的 `.next`。

3. 生成正式构建。

```bash
npm run app:build
```

如果本地还开着 `npm run app:preview` 或 `npm run app:start`，`app:build` 会提示先停掉再正式构建。

4. 确认正式服务可以启动。

```bash
npm run app:start
```

`app:start` 会检查 `.next/BUILD_ID`、数据目录读写权限和端口占用；默认端口是 3035。

5. 确认数据目录会被部署环境持久保存；必要时设置 `SUPER_FAMILY_DATA_DIR`，不要放在会随发布清空的临时目录。

6. 确认 HTTPS、域名和反向代理配置完成后，再让家人正式使用。

7. 正式部署建议设置 `AUTH_SECRET` 环境变量，用于登录 cookie 签名。可以用下面命令生成：

```bash
npm run auth:secret
```
